# MovieBox Android App 0.1.3

Version code 6. Install over the same native app to preserve its library; do not uninstall. This project is separate from the Android patch and Android TV app. The owner reported a successful in-app update with data preserved on 25 November 2026; read-only inspection confirmed the installed version and exact APK identity.

## What changed

- Open the portrait watch page without a temporary Play button during autoplay. The pending video frame keeps the same full-width 16:9 shape as playback.
- Use more compact player controls and aligned title tools, with existing touch, seek, rotation, subtitle and volume behavior retained in the checked scenarios.
- Search and navigation sit over taller home artwork; tapping a featured card opens that card's own title.
- See title-specific related suggestions after playback starts or a source lookup fails. Suggestions are optional and do not block playback startup.
- Keep Audio available after a source failure. Retry and episode navigation preserve the selected audio edition; delayed responses cannot silently replace it with a previous title.
- Start with the first usable advertised quality instead of waiting for every quality lookup. No unavailable quality is invented or relabeled.
- Distinguish a confirmed unavailable movie's **Coming soon** state from a connection, authorization or malformed-response error. **Check availability** tries a new source lookup; a cached display state cannot block newly available playback.
- Remove the native 18+ restriction and its Settings switch. External service access rules remain unchanged, and there is no parental-control guarantee.

## Verification and limits

The signed production APK passed **38 release unit tests**, release build and lint, **72 combined Android 6/API 23 emulator scenarios**, and **one additional stable portrait/landscape visual and interaction scenario**. Independent HQ review examined the scoped implementation, runtime results and final captures. These counts are separate checks, not a count of all possible behaviors or devices.

An additional two-phase same-signer upgrade probe passed on a disposable emulator: the exact published 0.1.2 APK was seeded with an owned saved title, progress, audio/subtitle preferences and recent searches, then updated in place to this exact 0.1.3 APK. Verification preserved all those fixtures. This controlled probe is separate from the later owner-reported physical update.

The runtime suite uses owned sample media and controlled API metadata. Exact-title comparison with the original installed app confirmed one reported entry was marked Coming soon there too; it does not establish availability of every title. Earlier live-service timing belongs to its own earlier candidate and is not claimed as this final build's physical acceptance or a faster-than-original benchmark.

Read-only package inspection independently confirmed version 0.1.3/build 6 and the exact APK hash above. No agent installation or data clear was performed. Data preservation is owner-reported; broader physical playback, other devices, complete upstream UI/feature parity and universal service availability remain unverified. No zero-buffering, instant-loading or all-device guarantee is made.

The current-build availability images are actual Android 6 emulator UI rendering synthetic, owned metadata. They are not current live-catalogue or phone captures. The older home/icon images remain explicitly historical 0.1.1 phone captures.

## Update handoff

The installed app checks this repository's public latest release. A new commit, draft or prerelease does not appear as an available update. The complete matching non-draft, non-prerelease APK release must be published before it can be offered by the updater.

The existing certificate and package are retained. Actual installation remains an Android/user action; no silent update occurs. Preserve the previous accepted release and report version, Android version and reproduction steps if a problem appears. Do not share private tokens or signed video URLs.

The owner update confirmation is a documentation addendum. The published APK, source ZIP, tag and checksums are unchanged; the original source ZIP remains the release-time snapshot rather than a rewritten archive of these later notes.
